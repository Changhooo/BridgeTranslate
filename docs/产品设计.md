# 桥译 · 产品设计

## 产品目标

让用户在 Claude 网页中以中文组织问题、以英文发送，并在同一条回答附近阅读中文。使用用户自带的模型接口，减少翻译软件之间的切换。

根据本次确认，主要交互直接发生在网页内；侧边栏用于设置和备用手动翻译。

## 默认选择

| 项目 | 本版行为 | 原因 |
| --- | --- | --- |
| 浏览器 | 桌面 Chrome 116+，Edge 待实机确认 | 使用 Manifest V3 与 Side Panel API |
| 目标网站 | `https://claude.ai/` | 先完成一个网站的提问与回答适配 |
| 提问翻译 | 翻译按钮只替换；可选启用 Enter 翻译后发送，默认关闭 | 保留手动检查方式，用户自行开启快捷发送 |
| 回车设置 | 工具条即时切换；设置页保存；本机记住 | 与自动译回答独立，关闭时保留网页原回车行为 |
| 输入撤销 | 当前框仍为刚生成的英文时可撤销 | 避免覆盖后续编辑 |
| 回答翻译 | 默认自动翻译最新回答；旧回答手动 | 控制费用，避免批量发送历史 |
| 翻译时机 | 已出现后续内容块且稳定约 250 毫秒的段落可在生成中翻译；最后一段等后续内容块或结束 | 无明确结束标记时末段以约 1.4 秒稳定等待作后备 |
| 显示方式 | 默认每个英文段落下紧接中文；仍可切原文或中文 | 代码块与多媒体保持原位置，便于上下对照 |
| 文字与对象 | 仅普通文字送翻译；公式、图片、SVG、Canvas、代码保留原节点 | 避免多媒体和代码内容被改动 |
| 排版字号 | 中文模式保留现有 Markdown DOM；双语中文按源节点字号显示 | 小字号提示不变成正文或标题 |
| 长回答 | 最多两个请求并发，逐段显示；后文追加保留前文译文 | 每个段落独立记录原文修订与翻译状态 |
| 复制 | 使用网页原代码复制；中文表格支持富表格／TSV／Markdown；全文完成后导出 Markdown | 不添加额外代码复制按钮；行内代码保留在中文语句中 |
| 密钥 | 默认会话内保存，可选择本机记住 | 用户自行选择便捷性 |
| 失败 | 失败段保留原文，已完成译文保留；暂停后手动重试 | 避免丢失草稿与反复计费 |

## 主要流程

1. 首次配置：打开设置 → 选择协议 → 填 URL、模型和 Key → 授权该 API 域名 → 测试当前表单 → 保存供网页翻译使用。测试不改变已保存配置。
2. 日常提问：默认手动翻译后由用户发送；可选开启「回车译后发送」，中文按 Enter → 翻译 → 校验当前草稿和会话 → 原生填入并验证 → 单次点击原发送按钮 → 检查网页反馈。Shift+Enter 换行，输入法确认回车不处理。
3. 提问异常：翻译时改写了原稿 → 保留当前提问框 → 展示英文预览供复制；发生 API 错误则保留原稿。
4. 回答阅读：生成中识别已稳定段落 → 提取该段普通文字 → 最多两个请求并发 → 中文紧跟该英文段落 → 继续接收后续段落 → 回答结束补译末段。
5. 切换会话：停止旧会话任务、清除临时撤销与预览；旧结果不能写入新会话。

## 数据流

| 内容 | 产生位置 | 使用位置 |
| --- | --- | --- |
| 中文提问 | Claude 网页的提问框 | 发送到用户配置的翻译 API |
| 英文提问 | 翻译 API 返回 | 替换原提问框；默认用户发送，可选 Enter 流程验证后单次点击原发送按钮 |
| 英文回答 | Claude 页面已有内容 | 当前指定回答的普通文字以编号 JSON 发送到翻译 API |
| 中文回答 | 翻译 API 返回 | 逐段双语区域按原字号展示；中文模式仅替换各已完成段的文字节点 |
| 公式、图片、代码 | Claude 页面已有内容 | 在本机保留，不发送翻译；代码可原样复制 |
| API Key | 插件设置页 | 插件后台构造 API 鉴权，不传给网页脚本 |
| 术语表 | 插件设置页 | 作为翻译接口的术语参考 |

插件不向 Claude 追加“请翻译”等额外对话指令。中文输入与译文显示在共享页面内，属于本版已接受的设计。

## 一致性规则

- 每个段落的同一份修订只请求一次；后续内容追加不清空或重译之前的已完成段落；失败需手动重试。
- 页面生成中不替换提问；允许翻译已有后续块且稳定的回答段落，仍在增长的末段先等待。
- 新原文与待提交结果不一致时，丢弃过时结果。
- 同一页面一次只运行一个翻译任务；提问到来时等待当前回答批次结束，再优先处理提问。提问锁延续到填入和发送确认结束。
- 英文结果包含汉字时不自动替换，显示预览供人工检查。
- 密钥不会在跨域切换 API 地址时自动沿用。
- 翻译结果用安全 DOM 文本节点显示，不执行模型返回的 HTML 或脚本。
- 返回片段必须有且仅有对应编号；校验整批结果后才写入文字。
- 原文切换只恢复仍由插件拥有的文字，网站后续更新的文字不会被旧缓存覆盖。
- 正在翻译时禁止把不完整表格或全文作为最终译文复制；中断保留清晰提示。
- 代码使用网站原有复制功能；中文表格完成后可在双语和中文模式复制；「复制中文」不随原文模式变成复制英文。
- 段落文字或结构变更会取消该段过时请求，禁止把旧结果写入新内容；其他段落不受影响。
- 列表译文放在对应列表项内，公式、图片、代码和原有交互节点不移除。
- 离开页面取消当前请求与待发送提问；页面暂停期间不重新启动回答任务，返回页面再检查。
- Enter 自动流程仅在可见、可编辑的提问框中，且对应开关已开启、内容含汉字时处理。英文和通常的修饰键组合沿用网页行为；自动流程运行中拦截重复提交。
- 翻译失败、仍有汉字、草稿改变、原生填入不生效、会话切换、取消或关闭开关，均不触发后续自动发送。
- 只点击与当前输入框关联的明确发送按钮或同一表单的提交按钮；缺失／禁用则保留英文供手动发送，不猜测其他按钮，也不调用 form.submit 绕过编辑器。
- 一次 Enter 操作最多点击一次发送；未确认网页反馈时报告不确定并停止，不自动重发。
- 手动翻译按钮始终不发送；已点击发送后不能通过取消撤回已提交的请求。

## 本版边界

不处理页面导航菜单、图片 OCR、附件、Artifact、内嵌代码编辑器和跨站通用翻译。并非通用协议转换器；其他私有 API 需要新增适配器。不会伪造身份、调整指纹或提供账号不受限的承诺。

侧边栏提供标题、列表、代码块、表格等 Markdown 安全排版，并过滤常见辅助标签和时间戳。

后续可考虑站点适配更新与可选术语标注；这些后续项目未计入当前能力。

## 输入交互

提问翻译采用点击触发。检测中文时在输入框旁显示按钮；不会根据每个输入事件调用模型或自动覆盖文字。「自动译回答」仅作用于回答。

优先识别当前获得焦点的可见输入框，兼容 generic contenteditable、plaintext-only 与 textarea；忽略隐藏的旧输入框与搜索框。中文输入法候选尚未确认时禁止翻译。编辑动作会检查实际填入结果；失败时显示英文预览，保留原文，不以单纯写入 DOM 代替编辑器状态更新。

## 配置兼容

新增 enterTranslateSend 布尔字段，默认 false。旧配置缺少该字段时按关闭处理；网页公开配置只返回该开关值，不暴露 Key。SET_ENTER_SEND 与 SET_AUTO 的写入串行执行，测试连接不保存表单中的开关变化。

# 桥译 · Windows 独立版

在桥译自己的窗口中输入中文，使用你提供的翻译模型生成英文，再填入 Claude Code（CC）。英文回答在桥译阅读区逐段翻译和显示。

**本版不使用 Mods、Hooks、MCP 或浏览器扩展，不改动 Claude 的安装文件或配置。** 它是独立 Windows 程序。旧 `desktop/` 目录中的 Mods 方案已被本版替代，不需要安装旧包。

## 下载与启动

1. 下载 `BridgeTranslateWindows.zip`，完整解压到固定目录。
2. 打开文件夹，双击 `BridgeTranslate.exe`。
3. 不要只把 EXE 单独取出：同目录的 `Assets` 是公式字体与阅读界面资源。
4. 安装包面向 **Windows 10/11 x64**，已包含 .NET 运行时，无需安装 Python、Node.js 或开发工具。
5. 完整排版依赖 Microsoft Edge WebView2 Runtime。多数新系统已具备；缺少时程序会回退为纯 Markdown 文字阅读。需要完整排版可从 [微软官方页面](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)安装 Evergreen Runtime。

程序未做代码签名。请按设备自身的软件运行策略使用，不需要管理员权限。此包已交叉编译为 Windows GUI EXE，但尚未在真实 Windows CC 桌面上完成验收。

## 如果装过旧 Mods 版

先退出 CC，使用旧包的「卸载桌面版.cmd」移除旧插件路径登记，再重启 CC。独立版不会自动修改旧配置。

如果只使用过浏览器版，无需卸载浏览器扩展；它不影响这个程序的运行。

## 先配置翻译模型

展开左下方「翻译模型设置」。填写：

| 字段 | 说明 |
| --- | --- |
| 接口协议 | Chat Completions、Responses、Anthropic Messages 或 Gemini |
| API URL | 服务商的 API 地址，不是聊天网站首页 |
| 模型 ID | 你的账号实际有权调用的准确 model ID |
| API Key | 翻译服务商的密钥 |
| 鉴权 | 一般选「按协议自动」；本机无密钥服务选「无密钥」 |
| 术语表 | 可选，例如 `离焦距离 = defocus distance` |

常见地址形式：

| 协议 | 示例（请替换为真实服务商地址） |
| --- | --- |
| Chat Completions | `https://api.example.com/v1` 或完整 `/v1/chat/completions` |
| Responses | `https://api.example.com/v1` 或完整 `/v1/responses` |
| Anthropic Messages | `https://api.example.com/v1` 或完整 `/v1/messages` |
| Gemini | `https://generativelanguage.googleapis.com/v1beta` |
| 本机兼容服务 | `http://127.0.0.1:1234/v1` |

支持 HTTPS；HTTP 仅允许 `localhost`、`127.0.0.1`。特殊网关请填写完整生成接口地址。四类协议之外的私有接口不能仅凭 URL 直接兼容。

点击「测试当前配置」，成功后点击「保存配置」。测试只发 `Hello.`，不会自动保存。当前 Chat 请求使用 `max_tokens`，输出上限 4096；不接受该参数的模型需要适配后使用。

密钥使用 Windows DPAPI 按当前用户加密，配置保存在 `%LOCALAPPDATA%\BridgeTranslate\settings.json`。不写入 CC 或网页阅读区。更换 Windows 用户或电脑后，原加密密钥通常不能直接解密，应重新填写。可点击「删除密钥」清除本程序保存的 Key。

## 连接 CC 与绑定控件

1. 打开官方 CC 桌面应用，进入你要使用的 Code 本机会话。
2. 在桥译点击「刷新窗口」，从列表选中正确的 Claude 窗口。
3. 点击「连接所选窗口」，确认显示的窗口标题正确。
4. 点击「绑定输入框」。程序列出该窗口暴露的可访问控件，按名称、尺寸及已有文字预览选择 **原提问框**。
5. 如要使用发送功能，再点击「绑定发送按钮」，明确选择 CC 原来的发送按钮。
6. 首次先生成一句简短英文，使用「填入 CC」验收。确认填入位置正确之后，再按需使用自动发送。

不要绑定搜索框、取消按钮或其他会话的控件。目标控件关闭、重新创建或无法访问时需要重新绑定。程序不会根据屏幕坐标猜测输入位置。

CC 的不同版本不一定暴露相同的 UI Automation 控件。无法识别时仍可以使用桥译的「复制英文」并手动粘贴；不能把交叉编译通过理解为所有 CC 版本的控件都能绑定。

## 日常提问

### 默认：先翻译，再手动发送

1. **在桥译左侧的中文输入框写问题**，完成中文输入法选词。
2. 点击「翻译成英文」。
3. 在英文预览中检查，也可以继续编辑。
4. 点击「填入 CC」，然后到 CC 自己发送；也可直接复制英文粘贴。
5. 如果你明确要立即发送，可点击「填入并发送」。

程序不会拦截你在 **CC 原输入框** 中按下的回车。直接在那里输入中文仍可能被 CC 原样发送。

### 可选：中文按 Enter 译后发送

这个开关默认关闭。主动勾选「可选：中文按 Enter 译后填入并发送」后，在**桥译中文框**里按 Enter，会先翻译再尝试填入和发送。Shift+Enter 换行，输入法处理中的 Enter 不作为普通提交回车。点击「保存配置」可保存这个选择。

自动流程会核对绑定窗口、进程、输入框身份和填入后的英文，最后只调用一次绑定的发送按钮。缺少绑定时保留英文预览；发送按钮不可用时保留已填入的英文供手动处理。

### 草稿保护与取消

- CC 输入框已有其他草稿时不自动覆盖。请先自行清空，再填入。
- 桥译翻译期间改写中文，会取消待处理的提问。
- 关闭自动发送、改变目标窗口或点击取消，会停止尚未执行的自动流程。
- 译文仍含汉字、接口出错或输入框未接受完整英文时不自动发送。
- 需要粘贴回退时，只在已绑定且确认获得焦点的输入框里粘贴英文；该操作会将英文放入系统剪贴板。
- 发送后未观察到输入框清空，会提示未确认；程序不会再次点击。请先查看 CC 会话，避免自己重复发送。

**请在等待翻译期间保持 CC 的目标会话不变。** 程序可核对窗口标题和控件身份，但没有 CC 内部的权威会话标识；同一窗口内部切换会话时，不一定总能检测出来。已发生的发送不能通过取消翻译撤回。

## 自动读取与翻译回答

### 推荐：选择当前本机会话 JSONL

1. 在阅读区点击「选择会话 JSONL」。
2. 选择你当前 CC 本机会话对应的 `.jsonl` 文件。
3. 常见目录是 `%USERPROFILE%\.claude\projects\` 下的项目子目录。可在文件选择器中按修改时间排序，核对与你当前会话对应的文件。不同桌面版本、运行环境与配置目录可能不同，不能保证一定在此路径。
4. 程序只读该文件，提取助手的普通 `text` 内容，忽略用户消息、思考字段、工具输入与工具结果。
5. 保持「自动译回答」开启，新文字写入文件后会被读取；已有完整段落先翻译，末段在结束或约 1.4 秒安静期后补译。

它不会自动寻找或遍历其他项目文件，也不会改写会话记录。切换 CC 会话后，请手动重新选择对应文件。

**即时程度取决于 CC 何时写盘。** 如果该版本只在完整消息结束后落盘，独立版就只能在那时读取，无法做到跟屏幕输出同速。约 700 毫秒的轮询只决定读取频率，不改变 CC 的写盘时机。长时间暂停后继续追加的末段可能重新翻译。

初次选择读取最近最多约 16 MiB 的记录，展示其中最后一条可用助手文字；后续只跟随追加内容。同一消息的追加会复用未变的段落。当前阅读区展示当前记录，不提供完整会话历史管理。

### 备用：绑定界面回答区域

点击「绑定界面回答区域」，明确选择 CC 暴露的回答文字控件。程序会跟随这个控件的文字变化。

界面文字不一定包含完整 Markdown，也可能只包含可见内容；请根据控件预览选择回答区域，不要选择整个应用或导航区域。此方式的可用性取决于 CC 的可访问性实现，需要在实际版本中验收。

### 通用备用：粘贴英文回答

在 CC 复制英文回答，在桥译点击「粘贴英文回答」，即可翻译。这个动作会停止之前的文件或界面跟随，避免其他来源覆盖粘贴的内容。

## 阅读、格式与复制

- 「原文／双语／中文」切换只改变桥译阅读区，不写回 CC。
- 双语将中文放在对应英文内容块下面；标题、列表、引用、加粗和表格按 Markdown 渲染。
- 代码块、行内代码、公式及图片链接由本机保护，不作为正文发送给翻译模型。图片像素不处理，不执行 OCR。
- 公式由安装包附带的 KaTeX 本机渲染，不向在线公式服务发送数据。
- 图片先显示加载按钮，只有你点击时才请求原 HTTPS 图片地址。
- 代码块可点击「复制代码」；表格可复制 TSV 或 Markdown；整条回答和译文完成后可「复制中文 Markdown」。
- TSV 可粘贴到 Excel 等软件；复制全文时公式保留 TeX、图片保留链接，不复制图片位图。

从会话记录只能取得文字和 Markdown，不能准确继承 CC 私有界面的字号、布局和图片交互。阅读区采用自己的标题层级、正文与代码字号。工具卡片、Diff、Artifact 和附件不会被重建。

## 不同开关的作用

| 开关或按钮 | 作用 |
| --- | --- |
| 可选 Enter 译后发送 | 只处理桥译中文框里的提交，默认关闭 |
| 自动译回答 | 只控制回答翻译，与提问自动发送无关 |
| 窗口置顶 | 让桥译保持在其他窗口上方 |
| 取消 | 取消待处理提问、暂停回答翻译；已经到达 API 的请求可能仍计费 |
| 翻译／重试 | 重试当前未完成或失败的文字段落，不自动循环扣费 |

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 列表里没有 CC | 先打开桌面窗口再刷新；本程序只列出进程名包含 Claude 的可见窗口 |
| 找不到可绑定的输入框 | 当前 CC 可能未暴露所需控件，改用复制英文；需要针对该版本实机适配 |
| 显示已有草稿 | 程序不覆盖未知内容，请在 CC 清空该框后再试 |
| 提示焦点改变 | 确认目标窗口及绑定正确；程序不会继续向其他窗口发粘贴按键 |
| 中文没有自动发送 | 默认关闭；开启后也只作用于桥译中文框 |
| 已点击但未确认发送 | 查看 CC 是否已有问题，勿直接重发 |
| 没有 JSONL | 当前可能是远程会话，或桌面版本保存在其他目录；可用界面绑定或手动粘贴 |
| 回答翻译延迟 | 先确认记录文件已经更新，再检查翻译模型速度与网络；没有写盘就没有新内容可读 |
| 401 / 403 | 检查 Key、账户与模型权限 |
| 404 | 检查完整接口路径、协议和 model ID |
| 429 | 检查余额或频率，稍后手动重试 |
| 输出截断或参数不兼容 | 更换兼容模型或拆分内容；当前 Chat 适配使用 `max_tokens` |
| 阅读区只有原始 Markdown | 安装或修复微软 WebView2 Runtime，然后重启桥译 |
| 改了 API 但失败段没恢复 | 点击「翻译／重试」；失败段不会自行反复请求 |

## 数据与卸载

中文草稿先在桥译窗口处理。翻译服务商可以看到发送给它的文字；CC 正常发送流程只收到程序实际填入的英文。桥译不会把中文译文、翻译提示词或 Key 作为附加指令送入 CC 对话。

这不是对操作系统、CC 的屏幕读取能力、其他软件或平台日志作出不可见承诺，也不保证账号不受平台限制。

程序无自有服务器、遥测或启动项。草稿与译文不建立持久历史。退出并删除解压目录即可移除程序；需要同时删除设置与加密 Key 时，可删除 `%LOCALAPPDATA%\BridgeTranslate`。请先关闭桥译，避免其正在使用阅读区缓存。

Windows 桌面应用没有 Chrome 无痕开关。浏览器版的无痕使用方法仍见项目 `docs/使用指南.md`。

## 验证与源码构建

详见 [验证记录](验证记录.md)。本包已经 Windows x64 交叉编译，但 UI Automation、中文输入法、DPAPI、WebView2 和真实 CC 输入／发送仍需 Windows 实测。

开发者安装 .NET 8 SDK，在 `windows` 目录运行：

```powershell
dotnet run --project .\BridgeTranslate.Checks -c Release
dotnet publish .\BridgeTranslate.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

第三方组件许可证随包放在 `LICENSES`，公式字体许可也保留在 Assets 中。
